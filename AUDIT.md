# Глобальный аудит Discography Analyzer 1.7.0

Дата: 2026-10-14. Ветка: `arena/3512578b-discography-analyzer` (10 коммитов поверх `c8b91dd`).

## 1. Методика

Аудит проводился «по Карпатому»: сначала понять данные и код целиком, затем
измерить, затем менять по одному хирургическому шагу с проверкой каждого.

1. **Погружение.** Прочитаны все 35 файлов (~8 100 строк пакета и тестов),
   README, pyproject; выписаны контракты (правила классификации, инварианты
   копирования, структура XLSX).
2. **Базовая линия.** 64 теста зелёные; прогнаны `ruff` (расширенный набор
   правил), `mypy`, `vulture`.
3. **Данные.** В песочнице нет аудио и кодеков, поэтому написан генератор
   валидных контейнеров MP3/FLAC/M4A/APE с тегами, обложками, дублями,
   вариациями и типовыми ошибками метаданных. Собраны две коллекции:
   406 файлов с известной «правдой» (405 треков: 333 уникальных, 48 дублей,
   24 вариации; аудит 18/25/13) и 5 052 файла для профилирования.
4. **Профилирование** `cProfile` по стадиям: сканирование → чтение
   метаданных → классификация → комплектность → аудит → экспорт.
5. **Изменения.** Каждое — отдельный коммит с регрессионным тестом, который
   падает на старом коде. После каждого шага: полный прогон тестов, `ruff`,
   прогон на коллекции с известной «правдой» и golden-сравнение результата
   анализа «до/после» по всем полям всех 5 051 треков, выпускам аудита и
   комплектности (различия — только случайные `uuid4`-идентификаторы).

Итог: 71 тест, `ruff check .` чистый, результаты анализа побитово те же,
отчёт XLSX сравнён по 112 110 ячейкам (значения, заливки, шрифты, границы,
выравнивание, ширины колонок) — 0 отличий.

## 3. Что исправлено (детали и цифры)

Все замеры — wall clock, без профилировщика, 5 051 файл, 2 vCPU, SSD.

### 3.1 Экспорт XLSX: O(n²) → O(n) — `perf(exporter)`

`_style_data_row` обращалась к строке через `sheet[row]`. В openpyxl это
`iter_rows(min_row=row, max_row=row)` с `max_col=self.max_column`, а
`max_column` — полный проход по словарю `_cells`. На 5 000 строк × 5 листов
это ~10⁹ операций. `_fit_columns` аналогично пересчитывала `max_row` на каждую
колонку.

Исправление: явная адресация `sheet.cell(row, col)` при известном числе
колонок, однократный расчёт `max_row/max_column`, общие неизменяемые
объекты `Font/Border/Alignment/PatternFill` вместо создания на каждую ячейку.

Результат: все 5 листов, 23 колонки — **20.3 с → 3.8 с**. Остаток линейный:
присвоение стилей ячейкам (~2 с, хеширование в openpyxl), `workbook.save`
(~1 с), автоподбор ширины (~0.5 с). Тест считает обращения к `max_column`.

### 3.2 Чтение тегов: `if not tags` — `perf(metadata)`

`bool(EasyID3)` вызывает `keys()`, который перебирает все зарегистрированные
easy-ключи и дёргает каждый getter (≈50–170 мкс). Хелперы `_first/_values`
делали это на каждое поле каждого файла. В профиле это была самая дорогая
операция (44 % времени под профилировщиком).

Исправление: `if tags is None`. Анализ всей коллекции **6.9 с → 3.4 с** при
побитово тех же результатах.

### 3.3 Сохранение правок не меняет версию ID3 — `fix(metadata_writer)`

`mutagen` по умолчанию пишет ID3v2.4. Подтверждено экспериментально:
после «безопасного исправления разделителей» файл ID3v2.3 становился
ID3v2.4 (`TYER→TDRC`, UTF-8 кадры). Это противоречит контракту диалога
(«минимальное проверяемое изменение») и ломает чтение тегов в проводнике
Windows, WMP и части автомагнитол.

Исправление: версия контейнера читается до правки, при v2.3 передаётся
`v2_version=3` (mutagen корректно конвертирует кадры и восстанавливает
v2.4-представление в памяти). Сквозной тест на настоящем MP3.

### 3.4 Комментарий MP3 — `fix(metadata)`

Кадры комментариев в ID3 имеют ключ `COMM:<desc>:<lang>`, поэтому поиск по
`Comment/COMMENT` никогда не срабатывал: колонка, инфо-панель и экспорт для
MP3 были всегда пустыми. Берётся стандартный комментарий (пустой `desc`);
технические `COMM:iTunNORM` и т. п. остаются только в полном списке тегов.

### 3.5 Ошибка обложки ≠ ошибка файла — `fix(metadata)`

Pillow сообщает о битых изображениях не только `OSError/ValueError`, но и
`SyntaxError` (обрезанные чанки PNG) и `DecompressionBombError` (обложки
> ~179 Мп). Они пролетали мимо `_cover_details`, и файл целиком получал
`metadata_errors`, хотя все теги были прочитаны. Теперь это `cover_error`.

### 3.6 Один путь извлечения обложки — `refactor(metadata)`

`_extract_cover_details` (аудит) и `read_embedded_cover` (предпросмотр)
дублировали ~35 строк и расходились в выборе картинки для FLAC. Общий
`_embedded_cover()` гарантирует, что пользователь видит ту же обложку, хеш
и размеры которой сравнивал аудит.

### 3.7 FLAC/APE парсятся один раз — `perf(metadata)`

Только ID3 и MP4 имеют отдельное «easy»-представление; для остальных
`mutagen.File(easy=True/False)` возвращает один и тот же класс, и второй
вызов лишь повторно читал весь блок тегов (с обложками в мегабайты) с диска.
На синтетике выигрыш 7 %, на реальных FLAC с большими обложками и на NAS —
существенно больше (в два раза меньше чтений).

### 3.8–3.10 UI, типизация, инфраструктура

- `_clear_results()` вместо трёх копий блока сброса; убраны мёртвые
  `getattr/hasattr` (атрибуты всегда создаются в `__init__/_build_ui`);
  после ошибки анализа теперь очищаются инфо-панель и обложка.
- Диалог экспорта фиксирует `result` при открытии; три реальных замечания
  mypy устранены (остальные — шум tkinter-стабов).
- `[tool.ruff]` в `pyproject.toml` (консервативный набор правил),
  применены механические правки; `.github/workflows/tests.yml`
  (Ubuntu + Windows, Python 3.10/3.12, `ruff` + `unittest`);
  `discography_analyzer/__main__.py`; README дополнен.

Важная деталь: подсказку ruff `SIM118` (`for key in tags` вместо
`tags.keys()`) в `metadata.py` применять **нельзя** — Vorbis-комментарии
итерируются как список пар `(key, value)`, и «очевидная» правка сломала бы
FLAC. Отмечено `noqa` с пояснением.

## 4. Предложения (требуют решения автора)

### P2

**4.1 Пропускать скрытые файлы при сканировании** (`scanner.py`,
`_collect_files`). Скрытые каталоги уже пропускаются, файлы — нет. macOS
оставляет на SMB/USB-томах AppleDouble-файлы `._01 - Song.mp3`; они
попадают в анализ как MP3, дают «ошибка метаданных» и мусор в статистике.
Патч — одна строка `if name.startswith("."): continue` в обоих ветках
(и симметричный тест). Не применял: меняет состав анализируемых файлов.

**4.2 Параллельное чтение метаданных** (`scanner.py`, `analyze_collection`).
После оптимизаций чтение стоит ~0.6 мс/файл на SSD, т. е. упирается в CPU и
GIL, где потоки не помогут. Но на NAS/HDD время определяется задержкой
открытия файла, и `ThreadPoolExecutor(max_workers=4)` с `executor.map`
по чанкам даст 2–4×. Нужно сохранить: порядок треков (map сохраняет),
семантику `stop_event` (проверять между чанками), прогресс (по завершении
чанка). Рекомендую делать с реальной коллекцией на NAS и замером «до/после».

**4.3 Разделить `ui.py`** (2 487 строк) без изменения поведения:
`theme.py` (палитры и `apply_theme`), `export_dialog.py` (как уже сделано
для копирования и аудита), `settings_dialog.py`, и чистая функция
`track_info_text(track) -> str` — её можно покрыть тестами без Tk.
Делать по одному модулю за коммит; критерий — тесты и ручной прогон UI.

### P3

**4.4 Детерминированный `duplicate_group_id`** (`classifier.py:157`):
`min(component)` по случайным uuid меняется от запуска к запуску. Если поле
когда-нибудь выйдет в экспорт (сейчас оно не используется — `vulture`),
выбирать представителя по `relative_path`. Вместе с этим стоит либо
показать группу в отчёте, либо удалить поле.

**4.5 Дубли внутри вариаций.** Две одинаковые копии «Song (Live)» в разных
папках обе получают статус «Вариация»; дубль между ними виден только
косвенно (план копирования схлопывает их через `_variation_identity`).
Варианты: отмечать вторую копию как «Дубль» с источником-вариацией или
хотя бы выводить это в лист «Дубликаты».

**4.6 Дата создания.** `st_ctime` — время создания только на Windows. Для
переносимости: `getattr(stat, "st_birthtime", stat.st_ctime)`.

**4.7 Серьёзность «нет встроенной обложки».** Сейчас ERROR даже когда в
папке лежит `cover.jpg` и аудит сам предлагает «Встроить файл cover.jpg».
Продуктовое решение: ERROR только когда нет ни встроенной, ни внешней
обложки; при наличии внешней — WARNING. Это снизит шум в списке ошибок для
коллекций, где обложки традиционно хранятся файлами рядом.

**4.8 Гигиена.** `__version__` читать из метаданных пакета
(`importlib.metadata.version`) вместо дублирования; заглушку «Утилиты»
скрыть до реализации; диалогам копирования/аудита разрешить изменение
размера по вертикали (длинные списки файлов); `_sort_key` вызывает
`table_value` для каждого трека при каждой сортировке — можно кэшировать
ключ на время сортировки (заметно только на десятках тысяч строк).

**4.9 Атомарное копирование.** `execute_copy_plan` пишет `shutil.copy2`
сразу в конечное имя. Остановка, падение или обрыв сети на середине файла
оставляют в приёмнике усечённую копию с «нормальным» именем, которую
невозможно отличить от целой. Запись метаданных и экспорт уже используют
схему «временный файл → `os.replace`»; копированию стоит сделать так же
(`.<имя>.part` рядом с целью, удаление при ошибке/остановке) и
сверять размер с источником.

**4.10 Экспорт ещё в ~2 раза быстрее (опционально).** Оставшиеся ~2 с —
присвоение четырёх стилей каждой ячейке. `NamedStyle` на каждый статус
(одно присвоение `cell.style = name`) даёт ~5× на этом участке (замерено:
0.28 с против 1.56 с на 120 тыс. ячеек), но добавляет записи в галерею
«Стили ячеек» Excel. Делать только если это приемлемо для пользователей
отчёта.

## 5. Что проверено и признано здоровым

- Классификация: правила из README воспроизведены на синтетике 1:1
  (дубль только при идентичном названии, точной длительности и общем
  артисте; отсутствие обязательных данных ⇒ конфликт; вариация требует
  ровно один исходник); `O(n²)` только внутри групп `base_title`
  (0.2 с на 5 000 треков — менять не нужно).
- Копирование: источники только читаются, существующие файлы в приёмнике
  никогда не перезаписываются (`_available_destination`), плоский режим без
  коллизий имён; остановка корректно прерывает очередь.
- Экспорт: запись через временный файл в целевой папке, защита формул
  префиксом `'`, старый отчёт сохраняется при ошибке.
- Аудит метаданных и комплектность: 0.1 с на 5 000 треков, детерминированы.
- Настройки: безопасная загрузка с дефолтами и валидацией маркеров.

## 6. Как воспроизвести

```bash
python -m unittest discover -s tests -v   # 71 тест
ruff check .                              # конфигурация в pyproject.toml
```

Профилирование: `cProfile` вокруг `analyze_collection(...)` и
`export_xlsx(...)` на любой коллекции ≥ 1 000 файлов; ожидаемый профиль
после правок — верхние строки `mutagen.File`, `openpyxl ... __hash__`,
`workbook.save`, всё линейно по числу треков.
