# Changelog — Discography Analyzer

## [27.10.2026] — Версия 1.11.0: теги и обложки из интернета

Новая утилита отдельным пакетом `discography_analyzer/online/`; остальная
программа знает о нём одну строку реестра утилит.

**Что сделано:**

- **Утилита «Теги и обложки из интернета»** — для альбомов с пустыми тегами
  или без обложки ищет релиз в Apple Music (iTunes Search API, витрина на
  выбор), Deezer, MusicBrainz (обложки — Cover Art Archive) или Discogs (с
  личным токеном) и заполняет только пустые поля: название, исполнитель,
  альбом, исполнитель альбома, год, жанр, номер трека и общее число, номер
  диска у многодисковых релизов, обложка в теги и файл `cover.jpg`.
  Существующее значение никогда не заменяется.
- Выбор релиза перенесён из global-music-scanner-2: та же нормализация
  названий (без «(Remastered)», «- Single», диакритики латиницы; кириллица и
  японский не портятся), признаки издания и веса счёта Apple-выбора. Файлы
  сопоставляются с треками по номеру (из тега или имени файла), названию и
  длительности. Вариант выбирается сам, только если название, издание и
  исполнитель не противоречат тегам и совпало не меньше 80 % файлов.
- Запрос берётся из тегов или имён папок («Исполнитель - 1986 - Альбом»,
  папка исполнителя над «Albums», диски `CD1`/`CD2`); его можно исправить и
  повторить поиск, другой вариант выбирается из списка, у каждого — «совпало
  N из M», миниатюра обложки и ссылка на страницу релиза.
- Запись: одна временная копия на файл — теги, номера и обложка пишутся в
  неё, копия читается обратно `read_metadata` анализа, затем резервная копия
  и `os.replace` с прежними датами. ID3v2.3 остаётся v2.3. Файл обложки
  пишется через скрытый `.part` с проверкой SHA-256 и не перезаписывает
  существующий.
- Сеть — только стандартная библиотека (`urllib`, системный прокси и
  сертификаты): пауза между запросами к одному хосту (Apple 3 с,
  MusicBrainz 1,1 с, Discogs 1 с), один повтор при сбое, 429 и 5xx с учётом
  `Retry-After`, мгновенная остановка. Квота Deezer («error code 4»)
  пережидается. Ответы одной сессии кэшируются.
- Главное окно передаёт утилитам выбранную папку
  (`UtilityContext.selected_folder`); новая утилита начинает с неё.
- **Модульность** (ради отдельного пакета, поведение прежнее):
  `UtilityContext`/`UtilityPanel` вынесены в `utility_panel.py`, и панель
  можно держать в своём модуле без цикла импортов; `BackgroundUtilityPanel`
  даёт поток, опрос событий, «Остановить» и защиту от закрытия;
  `fileops.iter_folders`/`list_audio_files` заменили приватные
  `_iter_folders`/`_audio_files`, которые `cover_extraction` брал из
  `cover_embedding`; `fileops.write_new_file`,
  `cover_embedding.cover_image_from_bytes` и
  `metadata_writer.write_text_tags` вынуты из существующих функций, чтобы
  новый модуль пользовался теми же писателями, а не копиями.
- Версия 1.11.0 в `pyproject.toml`, `build_exe.spec` и `__init__.py`.
- Тесты: 157 → 213 (сеть подменяется, ответы — в формате API сервисов),
  `ruff check .` чистый. Окно проверено в Xvfb на поддельном сервисе: поиск,
  выбор варианта, «Искать снова», запись с подтверждением, повторная проверка.

**Ошибка/решение (найдено при разработке, до записи на диск):**

- Порог по счёту (75) пропускал трибьют с тем же названием и трек-листом:
  чужой исполнитель стоит только −80, и такой релиз набирал 95. Теперь
  автоматический выбор требует явного согласия названия, издания и
  исполнителя (`release_fits`), счёт только сортирует варианты.
- Вручную выбранное чужое издание (совпало 0 из 3) планировало файл обложки.
  Релиз без единого совпавшего трека теперь не планирует ничего.
- Резервная копия по умолчанию ложилась рядом с выбранной папкой альбома, то
  есть внутрь коллекции, и следующий анализ видел копии как дубли. Теперь она
  рядом с коллекцией, а папка копий внутри коллекции отвергается.
- Позиции подтреков Discogs («2-2a») попадали на диск 1; буквенный суффикс
  разрешён, позиция без диска наследует диск предыдущего трека.

**Не проверено:** ответы настоящих сервисов. В среде разработки сеть к
`itunes.apple.com`, `api.deezer.com`, `musicbrainz.org` и `api.discogs.com`
закрыта, поэтому адаптеры написаны по форматам, с которыми работает
global-music-scanner-2, и публичной документации API, а тесты используют
ответы того же вида. Нужна живая проверка на Windows: по одному альбому через
каждый сервис.

## [27.10.2026] — Версия 1.10.1: порядок плейлиста, права новых файлов, клавиши на Linux

Три ошибки, найденные при проверке 1.10.0 на влитом `main`; каждая
воспроизведена до исправления и закрыта отдельным коммитом с тестом.

**Что сделано:**

- Плейлист папки идёт в порядке дерева «По папкам»: папка за папкой, внутри —
  по диску и номеру (`_playlist_tracks` сортирует через `_folder_sort_key`).
- Новые `cover.jpg` (утилита «Обложка из тегов в файл папки») и `.m3u8`
  получают обычные права файла вместо `0600`: общий
  `fileops.create_partial_file` создаёт скрытый `.part` через
  `os.open(O_CREAT | O_EXCL, 0o666)`, и umask действует как для любого
  нового файла.
- Запасной путь горячих клавиш по `event.keycode` включается только для
  keysym `??` — его Tk отдаёт на Windows в русской раскладке.
- Версия 1.10.1 в `pyproject.toml`, `build_exe.spec` и запасном значении
  `__init__.py`; README уточняет порядок плейлиста.
- Тесты: 153 → 157, `ruff check .` чистый.

**Ошибка/решение:**

- Плейлист: поддерево сортировалось только по диску и номеру, без папки, и
  папка исполнителя с двумя альбомами давала `A1, B1, A2, B2`; так же
  перемешивались альбомы, разложенные по папкам CD1/CD2.
- Права: `tempfile.mkstemp` всегда создаёт `0600`, а `os.replace` сохраняет
  режим — на Linux и macOS новый `cover.jpg` был `-rw-------` рядом с
  `-rw-r--r--`, и медиасервер, работающий от другого пользователя (Plex,
  Jellyfin), не мог его прочитать. После правки при umask 022 — `-rw-r--r--`.
  На Windows режим влияет только на флаг «только чтение», поведение то же.
- Клавиши: запасной путь срабатывал для любого keysym длиннее одного символа.
  На X11 `event.keycode` — аппаратный код, и у F1, F3, F4 и KP_7 он равен 67,
  69, 70 и 79 — ASCII-кодам C, E, F и O. Проверено живыми нажатиями (XTEST)
  на влитом `main`: `Ctrl+F3` открывал экспорт, `Ctrl+KP_7` — выбор папки,
  `Ctrl+F1` копировал строки таблицы и выделенный текст фильтра. После правки
  эти сочетания ничего не делают, а `Ctrl+O`/`Ctrl+E`/`Ctrl+C` и вставка
  `Ctrl+V` в русской раскладке работают; путь Windows не изменился.

## [27.10.2026] — Версия 1.10.0: качество звука, обложка из тегов, плейлист M3U8

**Что сделано:**

- **Аудит качества звука** — новая категория «Качество звука» находит
  альбомы, собранные из разных источников: формат файла отличается от
  строгого большинства (при ничьей — рекомендация каждому файлу), у lossy
  трека битрейт ниже 75 % медианы того же формата и хотя бы на 64 kbps ниже
  неё, у lossless трека частота или разрядность не совпадают с большинством.
  Автоисправлений и предложений нет: качество источника тегами не лечится.
  Замечания сами попадают во вкладку «Аудит», лист XLSX и сводку по папке.
- **Утилита «Обложка из тегов в файл папки»** — обратная операция к
  встраиванию: там, где файла обложки нет, а у большинства треков в тегах
  одна и та же картинка, сохраняет её как `cover.jpg`/`cover.png`/`cover.webp`
  для foobar2000, Kodi, Plex и проводника. Тип определяется по содержимому,
  GIF/BMP и битые картинки идут в проблемы без перекодирования, файл
  пишется скрытым временным файлом с проверкой SHA-256 и `os.replace`,
  существующий файл никогда не перезаписывается. Аудиофайлы не меняются,
  резервные копии не нужны.
- **Плейлист M3U8** — кнопка рядом с «Экспорт в XLSX»: выбранная строка-папка
  даёт всё поддерево в порядке диска и номера, иначе — видимые строки
  текущей вкладки в порядке экрана (вкладка «Уникальные» даёт плейлист без
  повторов). Пути относительно папки плейлиста (на другом диске Windows —
  абсолютные), `#EXTINF` с округлённой длительностью или `-1`, UTF-8 без BOM,
  запись через временный файл и `os.replace`.
- Уборка хвостов: удалён мёртвый `ui._files_word`; `__version__` читается из
  метаданных пакета с запасным значением и больше не расходится с
  `pyproject.toml`; флажок резервной копии в окне «Исправить замечания»
  подключён к общему параметру и запоминается; в заголовке `CODEBASE.md`
  сказано, что это снимок 1.7.0 без генератора, а не описание текущего кода.
- Версия 1.10.0 в `pyproject.toml` и `build_exe.spec`; README обновлён
  (аудит, вторая утилита, плейлист). Тесты: 126 → 153, `ruff` чистый.

**Ошибка/решение:**

- При прогоне на E:\ всплыло, что mutagen отдаёт битрейт в битах в секунду
  (320000), а порог «64 kbps» сравнивался как 64 бита: под правило попадал
  любой файл ниже 75 % медианы, а сообщение печатало «64000 kbps». Порог
  переведён в 64 000 bps, текст делится на 1000; проверено на реальных
  файлах 320 и 64 kbps — «Битрейт 64 kbps … (медиана 192 kbps)».
- Большинство обложек для новой утилиты считается только среди файлов с
  читаемой обложкой: файлы без картинки не голосуют, поэтому один FLAC с
  обложкой в папке из трёх всё равно даёт `cover.jpg`. Ничья (например,
  2 против 2) — пропуск с причиной «у треков разные обложки».
- Проверено вживую на Windows: 1.9.0 из PR #9 (горячие клавиши в русской
  раскладке починены запасным путём по `event.keycode`, подсветка папки с
  пропуском — пиксель `#591a1a`, сводка по папке, копирование при нехватке
  места, замена повреждённой обложки с сохранением задней, exe 1.9.0),
  затем E:\ целиком: 9922 трека, 12659 папок, 170 с, 11080 замечаний аудита,
  из них 121 по качеству звука в 25 альбомах (104 по формату, 17 по
  частоте/разрядности, 0 по битрейту). Вручную проверены три альбома:
  папка Ellie Goulding с 20 FLAC + 20 MP3 (ничья форматов — рекомендация
  верна), Madonna «Bedtime Stories» с 13 MP3 + 1 FLAC (предупреждение на
  FLAC верно), Erez Yaary «Memoria Technica» с 6 FLAC 48/24 и 3 FLAC 44.1/24
  (три рекомендации верны). Утилита обложек на копии записала `cover.jpg`,
  после неё аудит предлагает «Встроить файл cover.jpg», а сводка показывает
  «Файл обложки в папке: cover.jpg». Плейлист из папки на копии: 7 треков,
  все пути найдены, VLC открыл его без ошибок (код 0); foobar2000 на машине
  не установлен, AIMP автоматически не проверялся.
- Влито в main через PR #10 (merge `29c3184`); CI 4/4 на ветке и на main
  (Ubuntu + Windows × Python 3.10/3.12), тесты 153.

## [27.10.2026] — Версия 1.9.0: сводка по папке, русская раскладка, исправления по ревью

Ревью всего кода по принципам Karpathy: каждая находка воспроизведена на
реальных файлах до исправления, каждое исправление — отдельный коммит с
регрессионным тестом, который падает на старом коде.

**Что сделано:**

- **Новое — сводка по папке.** Выбор папки в дереве «По папкам» показывает в
  панели всё, что лежит внутри (альбом или всю дискографию исполнителя):
  файлы и подпапки, длительность, размер, форматы с частотой/разрядностью
  (FLAC, APE) или диапазоном битрейта (MP3, M4A), альбомы с годами,
  исполнителей, статусы, встроенные обложки и файл обложки в папке,
  проверку комплекта и итог аудита. Раньше панель оставалась на прошлом
  треке. Чистая функция `models.folder_summary_text`.
- **Новое — горячие клавиши:** `Ctrl+F` — к фильтру, `Esc` в фильтре —
  очистить, `Ctrl+C` в таблице — копировать выделенные строки.
- Тёмно-красная подсветка папок с нехваткой файлов (1.8.4) теперь видна:
  строка получает только тег `FolderGap`.
- `Ctrl+O`/`Ctrl+E`/`Ctrl+F` и `Ctrl+X`/`Ctrl+C`/`Ctrl+V` в полях ввода
  работают в русской раскладке и с Caps Lock.
- Сканер и утилита обложек пропускают скрытые файлы (`._*` от macOS,
  временные копии писателей после аварийного завершения).
- Копирование идёт через скрытый `.copy-*.part` и переименовывается только
  после успешной записи.
- «Заменять повреждённые обложки» заменяет только саму обложку: задняя
  обложка, буклет и другие встроенные картинки остаются (FLAC, MP3, M4A).
- Утилита на родительской папке анализа перезапускает анализ; любая ошибка
  Pillow в панели даёт «Обложка не распознана» вместо обложки прошлого
  трека; аудит предлагает тот же файл обложки, что встраивает утилита
  (общий `find_folder_cover`); склонения «Папка · 2 файла», «5 папок»,
  «замечаний: N».
- Версия 1.9.0 в `pyproject.toml` и `build_exe.spec`; README обновлён.
- Тесты: 110 → 124, `ruff check .` чистый.

**Ошибка/решение:**

- Подсветка 1.8.4: строке давались теги `("Folder", "FolderGap")` в
  расчёте, что последний перекрывает. В ttk (`ttkTagSet.c`, одинаково в
  Tk 8.6.13, 8.6.14 и 8.6.15) приоритет назначается при создании тега и
  побеждает созданный раньше — `Folder`. Замер пикселя в живом окне: было
  `#f7f3ed` (обычная папка), стало `#591a1a` / `#5a1c1c` (тёмная тема).
- Скрытые файлы: на настоящем FLAC оставшаяся временная копия
  `.01 Song-audit-….flac` становилась «Дубликатом» оригинала, и план
  копирования выбирал **её вместо настоящего трека** (точка сортируется
  раньше цифр); AppleDouble `._01 Song.flac` получал статус «Уникальный»,
  копировался в подборку и давал 12 замечаний аудита.
- Копирование: на настоящей tmpfs на 700 КБ (4 файла по 300 КБ) третий файл
  оставался обрезанным до 110 592 байт, четвёртый — пустым, оба с обычными
  именами; повторный запуск добавлял к ним копии «(2)». Теперь остаются
  только две целые копии и ни одного `.part`.
- Проверка на Windows: в русской раскладке Tk 8.6.15 отдаёт `keysym = "??"`
  для любой кириллической буквы (видно привязкой `<Control-KeyPress>` с
  выводом `event.keysym` и `event.keycode`), поэтому привязки к
  `Cyrillic_*` не срабатывали — ни с Caps Lock, ни без. Добавлен запасной
  путь по `event.keycode`: виртуальный код клавиши не зависит от раскладки.
  `_shortcut_by_keycode` обслуживает Ctrl+O/E/F/C, `_text_shortcut_by_keycode`
  — Ctrl+V/C/X в полях ввода. Проверено живыми нажатиями (SendInput) в
  en-US и ru-RU, с Caps Lock и без: срабатывают все сочетания, вставка,
  копирование и вырезание работают в фильтре и в окне «Дополнительно…».
- В том же прогоне на Windows: пиксель строки папки с пропуском — `#591a1a`
  (светлая тема), как и требовалось; сводка по папке и по папке исполнителя
  показывается, на 10 000 треках занимает 5 мс; копирование при нехватке
  места оставляет только целые файлы и ни одного `.copy-*.part`; замена
  повреждённой передней обложки сохраняет заднюю; `1.9.0.exe` запускается и
  проходит анализ.
- Раскладка: в живом окне под Xvfb (XTEST, `setxkbmap ru`) клавиша O даёт
  keysym `Cyrillic_shcha`, с Caps Lock — `O`, поэтому `<Control-o>` не
  срабатывал; вставка `Ctrl+V` в фильтр в русской раскладке тоже не
  работала. Привязки — латиница в обоих регистрах и кириллица той же
  клавиши; неизвестный сборке Tk keysym не помешает запуску. Под Windows
  вживую не проверялось: там нет тестового окружения.
- Обложки: FLAC с битой передней и валидной задней обложкой после замены
  терял заднюю. Для ID3 новая картинка берёт свободный ключ `APIC:<desc>`,
  чтобы не перезаписать сохраняемую с тем же именем; M4A проверен вручную
  на файле из ffmpeg.
- Обложка в панели: картинка больше ~179 Мп поднимала
  `DecompressionBombError` мимо `except`, и панель показывала обложку
  предыдущего трека.
- Влито в main через PR #9 (merge `cc1a0f8`); CI на ветке и на main — 4/4
  success (Ubuntu + Windows × Python 3.10/3.12), тесты 126.

## [25.10.2026] — Версия 1.8.4: папка с нехваткой файлов — тёмно-красная
