# Концепция: нормализованная медиатека

Документ — итог разбора архива `Tags-Discography-Normalizer` (47 скриптов
`01_…47_*.py` и `_patch41.py`, данные в `data/*.json`). Скрипты одноразовые:
пути зашиты (`t:\_Discography_2_Save\…`, `d:\Mimo\Scripts\…`), читают и пишут
только FLAC, правила местами заточены под двух исполнителей. Но вместе они
описывают **итоговый результат**, к которому должна приводить программа: не
список проблем, а приведённую в порядок медиатеку. Ниже — этот результат,
что из него уже есть в Discography Analyzer, что найдено при разборе и в каком
порядке переносить остальное.

Прогоны в архиве: Klaus Schulze (Qobuz) — 110 релизов, 86 полных и 24
неполных; Ariana Grande — 404 релиза: 102 полных, 3 неполных, 297 «только
композитор», 2 вынесены из-за длины пути.

## 1. Итоговый результат

### 1.1. Единица — издание, а не папка и не файл

- Релиз опознаётся по `BARCODE` (UPC): все файлы с одним баркодом — одно
  издание, даже если они разбросаны по нескольким папкам источника. Один
  альбом в двух изданиях — два релиза (`Irrlicht`: `0004228331272` и
  `0602557892826`).
- Полнота считается по тегам: `TRACKTOTAL` — сколько треков в издании,
  `DISCTOTAL` — сколько дисков, `TRACKNUMBER` — непрерывность.
- У релизов Qobuz `TRACKTOTAL` — итог **всего релиза**, а номера на каждом
  диске начинаются с 1: все 24 многодисковых релиза Klaus Schulze устроены так
  (например, 12 + 12 + 9 при `TRACKTOTAL=33`). Скрипт 05 потом сделал
  `TRACKNUMBER` сквозным (диск 2 продолжает диск 1).

### 1.2. Раскладка по корзинам

| Корзина | Что внутри |
|---|---|
| `… (Good)` | полные релизы исполнителя |
| `… (Bad)` | неполные; в каждой папке `MISSING_TRACKS.md` — чего нет и как докачать (поиск по BARCODE) |
| `… (Composer)` | исполнитель только автор музыки (есть в `COMPOSER`, нет в `ARTIST`/`ALBUMARTIST`) |
| вынесенные (`t:\_a`) | путь не влезает в 259 символов Windows |

### 1.3. Имена — функция тегов

- Папка релиза: `ГОД Альбом [A, B] (Qobuz, ЛЕЙБЛ, BARCODE) 24Bit`.
  - год без скобок (шаг 28), у лейбла год убран (шаг 6a);
  - `[A, B]` — только когда исполнителей ровно два; при трёх и больше скобки
    нет, состав — в `RELEASE_INFO.md`;
  - гость (исполнитель вне `ALBUMARTIST` меньше чем в 30 % треков) в имя папки
    не идёт (шаги 46–47);
  - ` 24Bit` — когда все файлы 24-битные (шаг 33);
  - не влезает в 259 символов — у своих релизов убирается скобка, а папки
    «Composer» выносятся в `t:\_a`.
- Многодисковый релиз — подпапки `CD1`, `CD2`, …
- Файл: `NN. Title.flac`, номер — по диску, `Title` проходит санитайзер
  (`: ` → ` - `, `/` → ` - `, `?` убирается, `"` → `'`, двойные пробелы и
  висячие дефисы чистятся). Трек с гостем: `NN. Title (Гость feat. Альбомный
  артист).flac`, а `ARTIST` становится `Гость (feat. Альбомный артист)`.
- «Composer»: `ГОД Артисты - Альбом (Qobuz, ЛЕЙБЛ, BARCODE)`.

### 1.4. Обложка

`cover.jpg` лежит в папке релиза, та же картинка встроена в каждый файл как
передняя обложка (тип 3); совпадение сверяется по MD5 (шаги 06, 26, 42).
Аудит отдельно отмечает обложки меньше 1000 px.

### 1.5. Теги

Один `ARTIST` со значением `A, B` вместо двух отдельных полей (шаг 07);
`COPYRIGHT` без удвоения `X X` (шаг 14); без `LYRICS=[Instrumental]`
(шаг 23); пробелы по краям и двойные пробелы убраны во всех текстовых тегах,
кроме `LYRICS` (шаг 29); единый `GENRE`; исправленные опечатки `ALBUM` и
`TITLE`, серии с ведущим нулём (`Vol. 01`), чтобы тома сортировались.

### 1.6. Отчёты в самой медиатеке

`_INDEX.md` (таблица релизов: год, альбом, тип, исполнители, лейбл,
BARCODE, треки, время, диски, качество, статус), `_TREE.md` (дерево
папок и файлов со статистикой), `_MISSING_SUMMARY.md`, `MISSING_TRACKS.md`
и `RELEASE_INFO.md` в папках релизов.

### 1.7. Тип релиза и полнота дискографии

- Тип Album / EP / Single: MusicBrainz по баркоду → Discogs → Wikipedia →
  Apple (по UPC, «- Single»/«- EP» в названии) → метка папки → правило. Тип по
  правилу помечается `*`. Правило (шаг 37): Album — от 7 треков или от 30
  минут; EP — 4–6 треков либо до трёх треков от 20 минут; иначе Single.
- Сверка с полной дискографией исполнителя (по UPC или по паре «название +
  число треков») → `… — отсутствующие релизы.xlsx` со ссылками на Apple, Qobuz,
  Tidal, Deezer, Beatport, Discogs (шаг 45).

### 1.8. Как скрипты меняют файлы

Сначала прогон без записи, запись — только с `--apply`. Повторный запуск
ничего не ломает: папка ищется по баркоду. Теги FLAC правятся на месте, а
разница в размере уходит в блок `PADDING`, чтобы аудио не сдвигалось. Длинные
пути открываются через `\\?\`. Исходник удаляется только после сверки каждого
файла с копией (шаг 11).

## 3. Что нашлось при разборе

1. **Ложные пропуски у релизов Qobuz.** Проверка комплекта считала
   `TRACKTOTAL` числом треков диска. У полного бокса 12 + 12 + 9 с
   `TRACKTOTAL=33` каждый диск получал «пропущены № 13 … 33», а папка
   окрашивалась бордовым. Исправлено в 1.18.0: итог, одинаковый на всех
   дисках и больший любого номера, считается итогом релиза.
2. **Ложные пропуски при сквозной нумерации.** После шага 05 диск 2
   начинается с 13 — проверка требовала на нём № 1 … 12. Исправлено:
   номера, продолжающие предыдущий диск, — одна последовательность.
3. **Неполный бокс нельзя разложить по дискам без внешних данных.** Скрипты
   держали таблицу `EXPLICIT` с числом треков каждого диска. Программа не
   угадывает: показывает «ещё N по итогу M, диск не определить» и «нет диска
   4», а дыры внутри дисков — с номерами.
4. **M4A.** Текстовые freeform-теги iTunes (`----:com.apple.iTunes:BARCODE`,
   `LABEL`) показывались как «двоичные данные»; теперь читаются как текст.

## 4. Что сделано в 1.18.0

- **Вкладка «Релизы».** Строка — издание (папка альбома вместе с подпапками
  `CD1`/`Disc 2` и тегом `Album`), под `[+]` — его треки по дискам и номерам.
  Столбцы: комплект (полный / без пропусков / не хватает N / нет диска / не
  проверить), треков `есть/всего · N CD`, альбом, тип (`*` — оценка),
  исполнители и гости, замечания, папка, лейбл, BARCODE (у трека — ISRC),
  обложка, год, жанр, время, качество, формат, размер. Сортировка своя, фильтр
  общий, «Развернуть всё»/«Свернуть всё» работают, правая кнопка открывает
  меню папки релиза («Заполнить теги из интернета…»), плейлист M3U8 строится
  по выбранному релизу.
- **Карточка релиза** в панели: состав и гости, тип и откуда он, лейбл,
  баркод, способ нумерации, длительность, качество, обложка (совпадает ли
  `cover.jpg` со встроенной), самый длинный путь, «Чего не хватает» с
  подсказкой искать по BARCODE, список треков.
- **Замечания релиза:** разные баркоды в одной папке, то же издание в другой
  папке, нет обложки или она встроена не везде, разные обложки в файлах, путь
  длиннее 259 символов.
- Проверка комплекта понимает три способа нумерации; папка релиза, которому
  не хватает треков по итогу или целого диска, окрашивается в «По папкам»,
  даже когда ни на одном диске нет дыры.
- Лист «Релизы» в XLSX и раздел «РЕЛИЗЫ» в сводке по папке.

## 5. Дорожная карта

Порядок выбран так, чтобы каждый шаг был полезен сам по себе и опирался на
вкладку «Релизы».

1. **«Имена по тегам»** — утилита переименования папок релизов и файлов по
   шаблону. Шаблоны по умолчанию — из архива: `{year} {album}{artists2}
   ({source}, {label}, {barcode}){24bit}` и `{track:02}. {title}`; источник
   (`Qobuz`) — часть шаблона, а не константа. Предпросмотр «сейчас → будет»,
   санитайзер из шага 22, проверка 259 символов с запасным шаблоном без
   скобки, журнал для отката, на диске ничего не перезаписывается.
2. **«Чистка тегов»** — правила шагов 07, 14, 23, 29: удвоенный `COPYRIGHT`,
   `LYRICS=[Instrumental]`, несколько `ARTIST` → одно `A, B`, пробелы во всех
   текстовых тегах, кроме `LYRICS`. Пишется так же, как сейчас: через
   временную копию с повторным чтением и резервной копией.
3. **Обложка = файл:** аудит «`cover.jpg` отличается от встроенной» и
   «обложка меньше 1000 px», выравнивание `cover.jpg` по встроенной (шаг 42).
4. **«Собрать нормализованную медиатеку»** — режим копирования по корзинам
   Good / Bad с `MISSING_TRACKS.md` и `RELEASE_INFO.md` (шаги 22, 23, 39) на
   основе окна «Копировать уникальные». Исходник не трогается.
5. **Тип релиза из сервисов** — MusicBrainz по баркоду, Apple по UPC, мастера
   Discogs; кэш рядом с `online_tags.json`, приоритет источников как в архиве.
6. **«Чего нет в коллекции»** — дискография исполнителя из сервиса против
   вкладки «Релизы» (UPC или «название + число треков»), лист XLSX со ссылками.
7. **Markdown-отчёты** (`_INDEX.md`, `_TREE.md`, `MISSING_TRACKS.md`) — по
   желанию, в выбранную папку.

### Что переносить не нужно

Зашитые пути и имена исполнителей (`MAIN = "ariana grande"`), таблицу
`EXPLICIT` для отдельных баркодов, правку FLAC на месте без повторного
чтения (в программе запись идёт через временную копию и сверку), удаление
источника без явной команды.
