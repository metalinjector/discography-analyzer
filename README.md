# Discography Analyzer

Настольная программа на Python для безопасного анализа локальной музыкальной
коллекции. Обычный анализ работает только на чтение: программа не удаляет,
не перемещает и не переименовывает исходную музыку. Изменение тегов возможно
только после отдельного предпросмотра и явного подтверждения пользователя.

## Возможности

- поиск MP3, FLAC, M4A и APE в выбранной папке и подпапках;
- продолжение анализа при единичных недоступных файлах с указанием количества
  пропусков в итоговом статусе;
- стабильный алфавитный порядок обхода файлов и папок между запусками;
- чтение основных, технических и пользовательских тегов через Mutagen;
- показ встроенных обложек;
- строгий поиск дубликатов по полностью одинаковому названию, точно одинаковой
  длительности без допуска и хотя бы одному общему артисту;
- непосредственные связи между файлами внутри общей группы дубликатов без
  ложного утверждения, что каждый файл совпадает с каждым;
- распознавание `feat.`, `ft.`, `&`, запятых и других разделителей артистов;
- связь ремикса, live-версии и другой вариации только с одним однозначным
  исходным файлом;
- раскрываемые группы `[+]` для дубликатов и вариаций: внутри всегда видны
  все связанные файлы, включая исходник вариации;
- статусы «Уникальный», «Дубликат», «Вариация» и «Конфликт»;
- собранные слева вкладки, плавный отложенный фильтр, сортировка,
  множественное выделение и копирование;
- ручное изменение ширины всех столбцов без автоматического возврата и кнопка
  автоподгонки по заголовкам и содержимому ячеек;
- обычный и древовидный режим просмотра структуры папок, кнопки быстрого
  разворачивания и сворачивания всего дерева; по умолчанию открывается
  «По папкам» с древовидным видом;
- сводка по папке: выбор папки в дереве «По папкам» показывает в панели всё,
  что лежит внутри неё (альбом или всю дискографию исполнителя) — файлы и
  подпапки, общую длительность и размер, форматы с частотой и разрядностью
  или диапазоном битрейта, альбомы с годами, исполнителей, статусы,
  встроенные обложки и файл обложки в папке, проверку комплекта и итог
  аудита;
- проверка пропущенных треков по `Track #`: как по итоговому значению `1/10`,
  так и по разрывам последовательности `1, 2, 3, 4, 6`;
- «№ трека (m/n)» — второй столбец таблицы (сразу после статуса) с числовой
  сортировкой по клику, файлы без номера уходят в конец; после анализа таблица
  автоматически открывается в порядке номеров (`1, 2, 3 …`), заголовок дерева
  («Группы и файлы» / «Структура папок») тоже сортирует — стрелка показывает
  направление;
- кнопка «Исправить нумерацию» с предпросмотром: выравнивает общий итог
  `Track #` по максимальному найденному номеру (`1/6` → `1/7`) с резервными
  копиями и без изменения самих номеров;
- строгая бело-оранжевая тема с тёплыми и металлическими оттенками,
  контрастный тёмный вариант и сохранение настроек;
- автоматический аудит метаданных с отдельной вкладкой: обязательные теги,
  Artist/Album Artist, нумерация, согласованность альбома, читаемость,
  встроенные обложки и качество звука (смешанные форматы, выпадающий битрейт,
  другая частота или разрядность);
- безопасная нормализация разделителей исполнителей и пробелов только после
  предпросмотра; исходный файл заменяется лишь после повторного чтения
  записанных тегов, резервная копия включена по умолчанию;
- плейлист M3U8 из выбранной папки или видимых строк: пути относительно
  папки плейлиста, `#EXTINF` с длительностью, UTF-8 без BOM;
- настраиваемый XLSX-отчёт с пятью видами листов, включая
  «Аудит метаданных», строками высотой
  `17,25`, оранжевыми заголовками и зелёными, голубыми и коралловыми
  смысловыми акцентами;
- атомарное сохранение XLSX: при ошибке записи ранее существовавший отчёт
  не повреждается;
- копирование уникальной подборки единым пронумерованным списком либо с
  сохранением исходной структуры папок;
- необязательная группировка порядка копирования по исполнителям: исполнители
  по алфавиту, релизы каждого исполнителя от новых дат к старым;
- отдельная необязательная папка «Не скопировано» для повторов и конфликтов,
  исключённых из основной подборки;
- окно «Утилиты» с обслуживанием коллекции: встраивание обложки из папки
  (`cover.jpeg` и аналоги) в теги файлов, у которых своей обложки нет, и
  обратная операция — сохранение встроенной обложки как `cover.jpg` рядом с
  аудио для плееров и медиатеки;
- «Теги и обложки из интернета»: для альбомов с пустыми тегами или без
  обложки релиз ищется в Apple Music, Deezer, MusicBrainz или Discogs, и
  заполняются только пустые поля — название, исполнитель, альбом, год, жанр,
  номера треков и дисков — и обложка.

## Установка

Нужен Python 3.10 или новее. В каталоге проекта выполните:

```bash
python -m pip install -r requirements.txt
```

На некоторых Linux-системах Tkinter устанавливается отдельно, например:

```bash
sudo apt install python3-tk
```

## Запуск

Windows:

```powershell
py app.py
```

Linux и macOS:

```bash
python3 app.py
```

Из любого каталога, если проект есть в `PYTHONPATH`:

```bash
python -m discography_analyzer
```

Либо после установки проекта:

```bash
python -m pip install .
discography-analyzer
```

## Основной сценарий

1. Нажмите «Выбрать...» и укажите корневую папку коллекции.
2. Выберите форматы, режим подпапок и использование тегов.
   Для контроля полноты альбомов оставьте включённым флажок
   «Проверять пропуски номеров треков».
3. Нажмите «Начать анализ» или `F5`.
4. Используйте вкладки, фильтр и сортировку.
   Нажмите `[+]` у дубликата или вариации, чтобы раскрыть связанные файлы.
   Во вкладке «По папкам» можно включить «Древовидный вид», а затем одной
   кнопкой развернуть или свернуть всю структуру.
5. Выберите строку для полной информации и обложки. Выбор папки в дереве
   «По папкам» показывает сводку по всему её содержимому.
6. Для связанной вариации используйте контекстное действие
   «Показать исходный трек».
7. Нажмите «Копировать уникальные...», чтобы сформировать подборку без
   повторяющихся дублей и вариаций.
8. Откройте вкладку «Аудит» для просмотра ошибок, предупреждений и
   рекомендаций. Для однозначных механических правок доступна кнопка
   «Исправить замечания...».
9. Нажмите «Экспорт в XLSX» для настройки и сохранения отчёта.
10. Нажмите «Плейлист M3U8...», чтобы сохранить плейлист для плеера:
    выбранная строка-папка даёт всё её поддерево в порядке дерева (папка за
    папкой, внутри — по диску и номеру трека), иначе в плейлист попадают
    видимые строки текущей вкладки в том порядке, в каком они на экране
    (так вкладка «Уникальные» даёт плейлист без повторов).

Горячие клавиши: `Ctrl+O` — выбрать папку, `Ctrl+E` — экспорт, `F5` — анализ,
`Ctrl+F` — перейти к фильтру (`Esc` в поле фильтра очищает его), `Ctrl+C` в
таблице — копировать выделенные строки. Сочетания работают и в русской
раскладке, и с включённым Caps Lock; так же работают `Ctrl+X`/`Ctrl+C`/`Ctrl+V`
в полях ввода.

## Правила классификации

Дубликат подтверждается только при выполнении всех условий:

1. названия полностью идентичны с учётом регистра и знаков;
2. точная длительность полностью идентична, без допуска;
3. совпадает хотя бы один артист.

Из-за этого `Artist A feat. Guest` и `Artist A` считаются имеющими общего
артиста. Известная разная длительность всегда означает разные треки.
Отсутствующие обязательные данные создают конфликт для ручной проверки.

Обозначение `Remix`, `Live` или другое само по себе не назначает статус
вариации. Требуется ровно один файл без обозначения версии, полностью
совпадающее базовое название и общий артист. При отсутствии исходника или при
нескольких возможных исходниках файл остаётся самостоятельным.

## Проверка комплектности альбомов

Проверка выполняется внутри каждой папки отдельно для каждого значения `Album`
и номера диска:

- при тегах `1/10`, `2/10` и т. д. программа проверяет весь диапазон до 10;
- при простых номерах без общего количества программа ищет внутренние разрывы;
- `TRACKTOTAL`, `TOTALTRACKS`, `DISCTOTAL` и MP4-атомы `trkn`/`disk`
  также учитываются;
- многодисковые издания проверяются по дискам раздельно;
- файлы без `Track #` и противоречивые итоговые значения помечаются отдельно.

Что означает пометка:

- `⚠ пропущены № …; ожидается N` — не хватает номеров внутри диапазона;
- `⚠ … без Track #: N; ожидается N` — часть файлов вообще без номера;
- `⚠ комплект полный; итоги в тегах: 6, 7` — все номера на месте, но файлы
  объявляют разное общее количество (теги 6-трекового издания плюс
  добавленный трек). Карточка файла в этом случае показывает
  `Итог в тегах: 6 (6 файлов), 7 (1 файл)` и не пишет «ожидается»: ничего не
  пропущено, расходится только `TRACKTOTAL`;
- `⚠ комплект полный; итог в теге меньше номера: 6 < 7` — во всех файлах итог
  один, но он меньше реально найденного последнего номера.

В дереве «По папкам» папка, у релиза которой по тегам не хватает файлов,
выделена тёмно-красным (почти бордовым) фоном с белым текстом — видно даже в
свёрнутом дереве, не открывая папку. Папки с расходящимися итогами или файлами
без `Track #` красным не помечаются: нехватка файлов там не доказана.

Если выделить папку, строку-предупреждение, трек или замечание аудита с такими
расхождениями, внизу появляется тёмно-серая кнопка «Исправить нумерацию (N)»
(в цвет шапки таблицы). Она
открывает окно, где для каждого файла видно `Сейчас 1/6 → Будет 1/7`: номера
остаются своими, выравнивается только общий итог по максимальному найденному
номеру. Строки можно снять с исправления, резервная копия включена по
умолчанию, запись идёт через временную копию с повторным чтением. Итог никогда
не понижается ниже уже объявленного, а файлы без `Track #` не изменяются и
перечисляются в окне.

Предупреждения видны в колонке «Проверка комплекта», карточке файла,
древовидном представлении, итоговой статистике и XLSX-отчёте.

## Аудит метаданных

После классификации программа автоматически проверяет каждый файл и
согласованность треков внутри папки/альбома:

- отсутствие `Title`, `Artist`, `Album`, `Album Artist`, даты и встроенной
  обложки;
- ошибки чтения аудио, тегов и повреждённые встроенные изображения;
- разделители и пробелы между исполнителями, например `Riana;Moby` →
  `Riana, Moby`;
- несогласованность `Artist` и `Album Artist`. Дополнительный приглашённый
  исполнитель считается рекомендацией для проверки, а не безусловной ошибкой;
- некорректные, отсутствующие и повторяющиеся номера треков и дисков;
- итог `Track #` меньше найденного на том же диске номера (например `1/6` при
  существующем треке 7): предупреждение на каждый такой файл с предложением
  `1/7`, но без автозамены — решать, входит ли трек в издание, должен человек;
- единичные отличия `Album`, `Album Artist`, даты и обложки от большинства
  треков того же альбома;
- качество звука — альбом, собранный из разных источников:
  - формат файла не совпадает со строгим большинством треков альбома
    (`MP3` среди `FLAC`): предупреждение; если преобладающего формата нет,
    рекомендация каждому файлу;
  - у lossy-трека (`MP3`, `M4A` без `ALAC`) битрейт ниже 75 % медианы того же
    формата в альбоме и хотя бы на 64 kbps ниже неё: предупреждение. Разброс
    VBR (например, 190–260 kbps) замечаний не даёт;
  - у lossless-трека (`FLAC`, `APE`, `ALAC`) частота или разрядность не
    совпадают с большинством: рекомендация, например
    «96 kHz/24 bit при 44.1 kHz/16 bit у большинства треков альбома».

  Эти замечания ничего не исправляют: качество источника не лечится тегами,
  поэтому решает человек. Пороги 75 % и 64 kbps — стартовые; если на реальной
  коллекции они дают ложные срабатывания, их подстраивают вместе с записью
  причины в CHANGELOG.

Замечания сгруппированы по файлам и раскрываются значком `[+]`. Ошибки,
предупреждения и рекомендации выделены разными контрастными цветами.
Автоматически исправляются только однозначные преобразования разделителей и
пробелов, выбранные пользователем в окне предпросмотра. Остальные предложения
остаются информационными и не меняют теги.

## Копирование уникальной подборки

После анализа кнопка «Копировать уникальные...» открывает отдельное окно:

- «Единым списком» помещает файлы непосредственно в выбранную папку и
  присваивает им имена вида
  `01 Исполнитель - Альбом (Год) - 05-Название.flac`;
- «С сохранением структуры папок» воссоздаёт относительные пути исходной
  коллекции;
- «Разобрать по исполнителям» сначала группирует исполнителей по алфавиту,
  затем располагает релизы каждого исполнителя от новых дат к старым;
- флажок «Также создать папку „Не скопировано“» сохраняет исключённые файлы
  тем же выбранным способом.

Отбор выполняется от старых дат к новым: сначала используется год из тега,
а при его отсутствии — дата файла. Уникальные треки сохраняются. Из
подтверждённых прямых дублей остаётся самый ранний доступный представитель.
Одинаковая вариация повторно не копируется, только если совпали её базовое
название, обозначение версии, точная длительность и хотя бы один артист.
Неполные данные не используются для опасного предположения об одинаковости:
такие вариации сохраняются, а файлы со статусом «Конфликт» относятся к
исключённым. Существующие файлы в папке назначения не перезаписываются.
Группировка по исполнителям меняет только порядок и нумерацию копирования,
но не правило выбора самого раннего представителя дубля.

## Утилиты

Кнопка «Утилиты» на панели инструментов открывает окно обслуживания
коллекции. Утилиты перечислены слева; каждая — отдельный модуль, и новую
можно добавить, не трогая остальные.

**«Обложки из папки в теги»** — для каждой папки с файлом обложки
(`cover.jpg`, `cover.jpeg`, `folder.png`, `front.*`, `albumart.*`) находит
аудиофайлы, в тегах которых нет читаемой картинки, и встраивает в них эту
обложку:

- папка коллекции по умолчанию берётся из главного окна; можно выбрать другую;
- обрабатываются все форматы программы: MP3, FLAC, M4A, APE; скрытые папки и
  папки из списка исключений пропускаются;
- сначала выполняется предпросмотр: какие папки и сколько файлов будет
  изменено, какая обложка выбрана и её размер; ничего не пишется до нажатия
  «Встроить обложки»;
- опция «Заменять повреждённые обложки» добавляет файлы с нечитаемой
  встроенной картинкой — без неё такие файлы только подсвечиваются в итогах;
  заменяется только сама обложка, а задняя обложка, буклет и другие
  встроенные картинки остаются в файле;
- каждый файл пишется через временную копию: обложка добавляется, читается
  обратно и сравнивается побайтово, и только после этого заменяет оригинал;
  при любой ошибке исходный файл остаётся нетронутым;
- флажок «Делать резервную копию перед записью» — общий параметр для всех
  трёх мест, где программа пишет теги: встраивание обложек, исправление
  нумерации и «Исправить замечания»; выбор запоминается в настройках и
  переживает перезапуск. Копии по умолчанию создаются рядом с коллекцией
  (`<коллекция>_cover_backup_<дата>`); папку можно выбрать, но не внутри
  обрабатываемой коллекции;
- после успешной записи окно само повторяет предпросмотр (обычно «вставлять
  нечего»), а главное окно перезапускает анализ, чтобы вкладка «Аудит» и
  колонка «Проверка комплекта» перестали показывать отсутствие обложек.

**«Обложка из тегов в файл папки»** — обратная операция: там, где файла
обложки нет, а у большинства треков в тегах лежит одна и та же картинка,
сохраняет её рядом с аудио как `cover.jpg`, `cover.png` или `cover.webp`:

- такие файлы читают foobar2000, Kodi, Plex и проводник Windows; сами
  аудиофайлы не изменяются, поэтому резервные копии не нужны;
- картинка выбирается по SHA-256: побеждает та, что встречается у строгого
  большинства треков с читаемой обложкой. Файлы без обложки не голосуют,
  ничья означает «у треков разные обложки» и папка пропускается с причиной;
- тип файла определяется по содержимому, а не по расширению; GIF, BMP и
  битые картинки попадают в список проблем и не перекодируются;
- предпросмотр показывает папку, файл-источник, размер в пикселях, «та же
  обложка у N из M файлов» и имя будущего файла; запись начинается только
  после подтверждения;
- файл пишется скрытым временным файлом, проверяется по SHA-256 и
  переименовывается; существующий файл обложки никогда не перезаписывается;
- после записи — повторный предпросмотр (обычно «записывать нечего») и
  перезапуск анализа: аудит начинает предлагать «Встроить файл cover.jpg»
  трекам без встроенной обложки, а сводка по папке показывает
  «Файл обложки в папке: cover.jpg».

**«Теги и обложки из интернета»** — для альбомов, где пусты теги или нет
обложки, находит релиз в онлайн-каталоге и заполняет **только пустые поля**:
значение, которое уже есть в файле, никогда не заменяется.

- Папка по умолчанию — выбранная в главном окне строка-папка (или папка
  выделенного трека), иначе вся коллекция. Альбом — это папка с аудиофайлами;
  у подпапок `CD1`, `Disc 2`, `Диск 3` название альбома берётся из
  родительской папки, а файлы сопоставляются с треками своего диска.
- Сервисы: **Apple Music** (iTunes Search API; витрина выбирается полем
  «Страна витрины»), **Deezer**, **MusicBrainz** с обложками из Cover Art
  Archive и **Discogs**. Discogs ищет только с личным токеном:
  discogs.com → Settings → Developers → «Generate new token»; токен вводится
  в поле «Токен Discogs» и хранится локально в `online_tags.json` рядом с
  `settings.json` программы. Qobuz и Tidal не подключены: их API требуют
  ключей приложения, а ключи их веб-плееров встраивать в программу нельзя.
- Что заполнять, выбирается флажками: название, исполнитель, альбом,
  исполнитель альбома (по умолчанию выключен — он пуст во многих хорошо
  оформленных альбомах), год, жанр, номер трека (и общее число, если указан
  только номер), номер диска (только у многодисковых релизов), обложка в теги
  и файл `cover.jpg` в папку. Обложка берётся, только если у альбома нет
  никакой: ни файла в папке, ни встроенной картинки; в остальных случаях
  помогут две утилиты выше.
- Запрос строится из тегов альбома, а без них — из имён папок
  («Исполнитель - 1986 - Альбом», «1986 - Альбом» в папке исполнителя,
  «Альбом (1986)»); служебные папки вроде «Albums» и «Singles» пропускаются.
  Запрос выбранного альбома можно исправить и нажать «Искать снова»; ручной
  запрос запоминается до закрытия окна.
- **«Искать и заполненные»** — по умолчанию утилита берёт только альбомы с
  пустыми полями, как и раньше. С этой галочкой в поиск попадают и полностью
  оформленные альбомы: ничего не записывается, но видно найденный релиз,
  «совпало N из M» и обложку — удобно сверить спорный альбом с сервисом.
  Пример: `(2015) Christmas & Chill` с заполненными тегами и `cover.jpeg` без
  галочки не ищется вовсе, с галочкой показывает 9 вариантов Apple Music.
- **Обложка варианта** видна в квадрате слева под списком альбомов, и в ручном
  режиме тоже: выбрали вариант — миниатюра сменилась сразу, ничего не
  записывая. Щелчок по ней открывает обложку крупно (до 600×600) с названием
  варианта в заголовке. Картинка скачивается один раз: те же байты идут и в
  миниатюру, и в крупный просмотр.
- **Выбор релиза: «Авто» или «Вручную»** (переключатель рядом с сервисом,
  выбор запоминается). В режиме «Авто» релиз выбирается сам, только если
  название и исполнитель не противоречат тегам и совпало не меньше 80 %
  файлов; иначе строка ждёт выбора. В режиме «Вручную» программа никогда не
  выбирает сама: показывает всё, что нашлось по запросу, а вы открываете
  альбом, вводите при необходимости исполнителя и название, нажимаете
  «Искать снова» и выбираете вариант из списка «Вариант» — у загруженных
  вариантов рядом стоит «совпало N из M». Пока вариант не выбран, альбом не
  записывается.
- Сам выбор релиза устроен так же, как в global-music-scanner-2: совпадение
  названия без «(Remastered)» и «- Single», исполнителя, издания (Live,
  Deluxe, Remastered 2011…), числа треков и года. Затем каждый файл
  сопоставляется с треком релиза по номеру, названию и длительности (±2 с).
  Позиция трека считается доводом только при однозначном диске: папка
  альбома против однодискового релиза или совпавший номер диска. Трибьют с
  тем же названием и трек-листом сам не выбирается.
- Дерево показывает альбомы и их файлы: найденный релиз, «совпало N из M»,
  трек источника для каждого файла и что именно будет записано. Внизу —
  миниатюра обложки и кнопка «Страница релиза».
- Запись идёт через временную копию каждого файла: теги, номера и обложка
  пишутся в неё, копия читается обратно тем же модулем, что и в анализе, и
  только потом заменяет оригинал. Резервные копии — по общему флажку; по
  умолчанию папка `<коллекция>_tags_backup_<дата>` рядом с коллекцией.
- Запросы идут с паузой: Apple допускает около 20 в минуту (3 с между
  запросами, обычно два-три запроса на альбом), MusicBrainz — один в секунду,
  Discogs — 60 в минуту. Поиск можно остановить; после трёх подряд альбомов без
  ответа сервиса поиск прерывается с причиной.
- **Прокси** — кнопка «Прокси...» рядом с выбором сервиса, рядом подпись с
  текущим выбором. Режимы: «Системный» (как в настройках Windows или в
  переменной `HTTPS_PROXY`; так было и раньше), «Без прокси» и «Свой прокси
  для отмеченных сервисов» — остальные сервисы идут по системным настройкам.
  Адрес: `http://хост:порт` (HTTP-прокси, HTTPS идёт через CONNECT) или
  `socks5://хост:порт` (SOCKS5; имя сайта разрешает сам прокси, чтобы не
  зависеть от местного DNS), с входом — `логин:пароль@хост:порт`. По
  умолчанию свой прокси отмечен для Deezer: он закрыт в части стран. Прокси
  сервиса действует и на его обложки (`dzcdn.net` у Deezer, `mzstatic.com` у
  Apple, `archive.org` у Cover Art Archive). «Проверить» делает пробный
  запрос к выбранному сервису с настройками из окна, ещё до сохранения:
  Deezer отвечает, из какой страны он видит запрос и открыт ли он там,
  Discogs — принят ли токен. Если Deezer сообщает, что закрыт, поиск один раз
  предупреждает об этом и продолжается. Настройки хранятся в
  `online_tags.json`, логин и пароль прокси — тоже, как есть; в подписи и в
  проверке они не показываются.
- Ограничения: год у Apple и Deezer — дата этого издания (у переиздания —
  год переиздания), жанр у Apple общий («Metal», «Rock»), у Discogs берётся
  первый стиль («Thrash»). Всё это видно в предпросмотре до записи.

## Тесты

```bash
python -m unittest discover -s tests -v
ruff check .
```

Те же команды выполняет CI (`.github/workflows/tests.yml`) на Ubuntu и
Windows для Python 3.10 и 3.12. Правила линтера заданы в `pyproject.toml`.

Тесты проверяют строгую классификацию, разбор вариаций и артистов, сохранение
настроек, структуру XLSX-отчёта и оба режима безопасного копирования. Тесты
онлайн-утилиты в сеть не ходят: ответы сервисов подставляются в формате их
API.
